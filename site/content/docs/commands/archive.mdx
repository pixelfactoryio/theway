---
title: /theway:archive
description: Move a finished change to changes/archive/ under a dated folder
---

Use it once the change is implemented, tested, deployed when that applies, and confirmed working.

## Usage

```text
/theway:archive <change-id>
```

## Steps

1. **Require an explicit instruction.** Archiving moves the folder, so it runs only when you name the change and say to archive it. Signals such as "it's merged" or "ship it" are not enough: it stops and asks.
2. **Verify completion.** It runs `~/.theway/bin/theway list <project>` and shows the task count. If the change is not at `N/N tasks done`, it shows the open numbered tasks and asks you to fix them or accept an override.
3. **Move to the archive:**

   ```bash
   ~/.theway/bin/theway archive <project> <change-id>
   # only when you accept the remaining open numbered tasks:
   ~/.theway/bin/theway archive <project> <change-id> --force
   ```

   The CLI also refuses while a numbered task is open, unless `--force` is given.
4. **Update project documentation** when needed, such as architecture docs in `docs/` with new patterns or conventions.
5. **Confirm** that the folder moved and where it is.

## Output

The whole change folder (`spec.md`, `tasks.md`, `design.md` and any other file) moves to:

```text
~/.theway/<project>/changes/archive/YYYY-MM-DD-<change-id>/
```

See [Changes](../concepts/changes.mdx#archive-format) and [`theway archive`](../cli.mdx#archive).
