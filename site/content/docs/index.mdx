theway is a set of Claude Code slash commands for planning and implementing changes in a codebase. It turns a request into a spec and an ordered task list, then implements the tasks, either inline in your session or through agents that open a pull request, run review rounds and drive CI green.

## Why spec-first

`/theway:engineering` writes only the spec, through the shipped `engineering` workflow. It investigates the code, settles the unknowns and records what it found, the decisions and their reasons, the risks and the tasks. `/theway:workflow` then writes the code from that spec, inline in your session or through agents, and stops with what it found and the options when the code contradicts the spec (see [`/theway:workflow`](./commands/workflow.mdx#steps)). For a small change with nothing to decide, `/theway:engineering --light` writes a shorter spec.

Every full spec (`/theway:engineering`) includes a [TAMM](./concepts/tamm.mdx) hardpoints table that names the Medium and High risks of the change and their countermeasures.

## Where things live

theway keeps its files in a data home, `~/.theway` by default, or the folder chosen at install (the install question or `--home`), or `THEWAY_HOME` (see [Installation](./installation.mdx#other-locations)). The config is `<home>/config.yaml`.

Each change is a folder under `<home>/projects/<key>/changes/`, where `<key>` is your repository's path with every non-alphanumeric character turned into `-` (`/home/you/code/my-api` gives `-home-you-code-my-api`). The folder holds `spec.md`, `change.yaml` (the tasks) and, when needed, `design.md` and `notes.md`. A finished change moves to `changes/archive/`, so the history of every change stays in the data home. See [Changes](./concepts/changes.mdx).

## Your own workflows

`/theway:workflow` runs a workflow: a YAML file listing the steps of a change, each run in your session or through agents. Each step uses a Markdown prompt and answers pass, fail or blocked; a fail can run a fix and the step again. theway ships `develop` (in your session) and `agents` (implement, review and pull request through agents), the two `engineering` workflows, and their prompts, as files in `<home>/workflows/` and `<home>/prompts/`. You add your own workflows and prompts there, or per project. See [Workflows](./concepts/workflows.mdx).
