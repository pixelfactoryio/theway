The configuration lives in `<home>/config.yaml`, where `<home>` is the data home: `~/.theway` by default, or the folder `THEWAY_HOME` named at install (see [Locations](./cli.mdx#locations); `theway path` prints it). Install writes it once and keeps your copy on later installs; the shipped version is always written to `<home>/config.default.yaml`, so you can compare the two.

`/theway:engineering`, `/theway:develop`, `/theway:develop-workflow` and `/theway:document` read this file; when it is missing, they tell you to run [`/theway:setup`](./commands/setup.mdx). `/theway:archive` and `/theway:list` only check that it exists and give the same instruction.

A `config.yaml` written by an earlier install may still have `changes:` and `templates:` sections, `interaction`, `develop` and `tamm_framework` entries under `standards:`, and `file` and `description` keys. Nothing reads them, and you can delete them.

## standards

Four standards are opt-in, each with a single `enabled` key: `/theway:engineering` and `/theway:document` read a standard's file only when its `enabled` is `true`. The other standards are always read and have no key: `interaction.md` by `/theway:engineering`, `/theway:develop`, `/theway:develop-workflow`, `/theway:document` and `/theway:archive`; `develop.md` by `/theway:develop` and `/theway:develop-workflow`; `tamm-framework.md` by `/theway:engineering`.

| Standard | `enabled` | File | Used for |
|----------|-----------|--------|----------|
| `standards.core_principles` | `false` | `<home>/data/standards/core-principles.md` | Architecture philosophy (simplicity, security, pragmatic technology) |
| `standards.sre` | `false` | `<home>/data/standards/sre.md` | SRE operational excellence (reliability, observability, automation) |
| `standards.web_development` | `false` | `<home>/data/standards/web-development.md` | Frontend, API and backend standards with web performance targets |
| `standards.quality` | `false` | `<home>/data/standards/quality.md` | Testing, deployment, monitoring and security expectations |

A `config.yaml` written by an earlier install has `standards.architecture` instead of these four entries, so they stay off until you copy them from `config.default.yaml` and set `enabled: true` on the ones you want.

## engineering

The spec review of [`/theway:engineering`](./commands/engineering.mdx#steps) (step 6). A key that is absent or invalid takes its default.

| Key | Default | Meaning |
|-----|---------|---------|
| `engineering.review_rounds` | `1` | Maximum review rounds per scaffold. A non-negative integer; `0` skips the review. |
| `engineering.models.critic` | `opus` | Model of the two critic agents: `opus` or `sonnet`. Any other value takes the default; `haiku` is never used. |

Each round spawns two critics. To lower the cost, put `engineering.models.critic` on `sonnet`, or set `review_rounds: 0` to skip the review.

## workflow

Caps for [`/theway:develop-workflow`](./commands/develop-workflow.mdx). A key that is absent or invalid takes its default.

| Key | Default | Meaning |
|-----|---------|---------|
| `workflow.review_rounds` | `1` | Review rounds per change. A non-negative integer; `0` skips the local review. |
| `workflow.ci_attempts` | `2` | CI attempts per change to reach green, re-runs included. A positive integer. |
| `workflow.open_pr` | `true` | After the local review, push the branch, open the PR and drive CI. `false` stops at the reviewed local branch: nothing is pushed, and a series stacks each change on a local branch created from the previous one. |

### workflow.models

The model each agent role of `/theway:develop-workflow` runs on. Each value is `opus` or `sonnet`; a key that is absent or holds any other value takes its default. `haiku` is never used.

| Key | Default | Agents |
|-----|---------|--------|
| `workflow.models.implementer` | `opus` | Implementers. When `opus`, `sonnet` is still allowed for mechanical tasks. |
| `workflow.models.reviewer` | `opus` | Adversarial reviewers and the fix check |
| `workflow.models.fix` | `opus` | Fix agents |
| `workflow.models.ci` | `sonnet` | CI polling and log fetching |

To lower the cost of a run, put `implementer`, `fix` and `ci` on `sonnet` and keep `reviewer` on `opus`, so the review still catches what a cheaper implementer misses. `review_rounds: 0` lowers it further by skipping the local review.
