A change is one unit of work: a folder with its spec and its tasks.

## Change IDs

A change ID is lowercase kebab-case and starts with one of five verbs: `add-`, `update-`, `refactor-`, `remove-` or `fix-`. For example `add-user-authentication`, `update-payment-api` or `fix-login-crash`.

A `fix-` change fixes a bug. `/theway:engineering` reproduces the bug before it writes anything and writes its spec from the fix template, which records the symptom, the reproduction, the root cause and the regression test. See [`/theway:engineering`](../commands/engineering.mdx). A small bug with a known cause can go through [`/theway:engineering --light`](../commands/engineering.mdx#light) instead: a short spec with the reproduction, and a regression test that fails before the fix and passes after it.

[`theway validate-id`](../cli.mdx#validate-id) checks the format, and `/theway:engineering` runs it on a standalone ID before it writes a change folder. A series' member IDs come from [`theway next-id`](../cli.mdx#next-id), which checks the series ID. A standalone ID must not end in a one- or two-digit number, since `-NN` is kept for series members.

## Series

A series is a set of dependent changes that share a `<series-id>`. Each member is `<series-id>-NN`, with a zero-padded two-digit ordinal starting at `01`, assigned in dependency order:

```text
add-user-auth-01
add-user-auth-02
add-user-auth-03
```

- [`theway next-id`](../cli.mdx#next-id) names the members of a new series: it validates the series ID and prints the next free IDs, counting active and archived members. Existing folders are never renamed or renumbered.
- With `--series`, `validate-id` rejects topic suffixes (`add-user-auth-login`), letter suffixes (`-a`, `-b`), unpadded numbers (`-1`), `-00` and double ordinals.
- Each member's `spec.md` has a line under its title: `**Series:** <series-id> — NN of TOTAL, depends on <series-id>-(NN-1)`. The `01` member states no dependency.

`/theway:workflow` takes the members in order. With a `pr` step in its workflow, it asks you before merging each PR and starts the next change once it is merged; without one, it stacks each change on a local branch created from the previous one.

## Folder layout

`<project>` is the name of your project directory.

```text
~/.theway/<project>/changes/
├── add-redis-cache/
│   ├── spec.md      # required: why, what, risks and Success Criteria
│   ├── tasks.md     # required: numbered tasks
│   └── design.md    # optional: contracts, data models, diagrams
└── archive/
    └── 2025-10-15-update-auth-middleware/
```

In `tasks.md`, only numbered checkbox lines are tasks: `- [ ] 1. …` or `- [x] 2a. …`. Other checkboxes are not counted.

## Archive format

An archived change keeps its whole folder and is named `YYYY-MM-DD-<change-id>`, with the local date of the archive:

```text
~/.theway/<project>/changes/archive/
├── 2025-10-10-add-logging-framework/
└── 2025-10-15-update-auth-middleware/
```
