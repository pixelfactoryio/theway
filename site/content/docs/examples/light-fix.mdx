This is an illustrative run on the sample project `my-api`, after the [full change](./full-change.mdx) added its rate limit.

## The request

A health probe that adds a query string gets throttled. The cause is known and the fix is local, so the light path fits:

```text
/theway:engineering --light fix-health-query-limited: GET /health?probe=1 counts against the rate limit
```

## The investigation

The command reproduced the bug before writing anything, with the server started from `createApp`'s defaults (60 requests per minute):

```bash
node -e 'import("./src/app.js").then((m) => m.createApp().listen(3000))' &
for i in $(seq 1 61); do curl -s -o /dev/null -w "%{http_code}\n" "http://localhost:3000/health?probe=1"; done | sort | uniq -c
```

```text
  60 404
   1 429
```

The bypass and the route both compare `req.url` to `"/health"` exactly, so the query string makes the request a normal one: it is counted, answered `404`, and limited on the 61st. Nothing in it is a decision: the README already calls `/health` exempt, and no contract changes.

## The spec

`<home>/my-api/changes/fix-health-query-limited/spec.md`:

````md
# Spec Analysis: Exempt /health with a query string from the rate limit
**Mode:** light

## Problem

`GET /health?probe=1` counts against the rate limit and gets `429` once the IP's quota is used. The bypass matches `req.url === "/health"` exactly (`src/app.js:15`), and so does the route (`src/app.js:21`), so any query string makes the request a normal, limited one.

## Evidence

- Is a query string ever stripped? Read `src/app.js`: no, `req.url` is compared as-is.
- Is the exemption meant to cover probes? Read `README.md`: "except `/health`", with no mention of the query.

**Command:**
```bash
node -e 'import("./src/app.js").then((m) => m.createApp().listen(3000))' &
for i in $(seq 1 61); do curl -s -o /dev/null -w "%{http_code}\n" "http://localhost:3000/health?probe=1"; done | sort | uniq -c
```

**Observed output:**
```text
  60 404
   1 429
```

**Expected result:** `61 200`: every probe is answered by `/health` and none is limited.

## Change

- `src/app.js`: take the path before `?` once (`req.url.split("?")[0]`), and use it for the `/health` bypass and the `/health` route.
- `test/app.test.js`: one HTTP test, "HTTP: /health with a query string is exempt".

Nothing else changes.

## Success Criteria

- [ ] The regression test `HTTP: /health with a query string is exempt` fails before the fix and passes with it
- [ ] The reproduction no longer reproduces: `for i in $(seq 1 61); do curl -s -o /dev/null -w "%{http_code}\n" "http://localhost:3000/health?probe=1"; done | sort | uniq -c` now shows `61 200`
- [ ] `npm test` passes
````
