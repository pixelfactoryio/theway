# Design System: theway dashboard and site

## Overview

**Creative North Star: "The Inset Panel"**

The dashboard is a desktop tool for a developer who keeps it open beside Claude Code sessions. It is built in Linear's layout and look: the sidebar sits straight on the app's cool ground with no border, and all the work happens in one inset panel with rounded corners, a hairline and a soft shadow, a step lighter than the ground. Across that panel's top runs a 44px header (the page's icon and path, its actions at the right), then small pill tabs for the page's views; under them the page, and on an item's page a docked panel of stacked property cards at the right.

Two modes share the panel. Lists, editors and the canvas are for operating: one-line 40px rows, sections that open with a tinted band, a sticky column head, IDs as small mono chips, the hover fill keeping the place. Every file the dashboard opens (a change's files, a prompt, a workflow's YAML) is edited whole in one code editor, as in Zed or VS Code: line numbers, the current line, a bar beside each changed line, a status bar under it, and Discard and Save at the right of the tab row; no field of a file is edited in place, and no title stands above a file. Documents are for reading (a Markdown file's Preview, an archived change's files): 17/24 body text in one 36rem column on the panel's left edge, about 65 characters a line. Everything is calm and dense: hierarchy comes from weight (400, 500, 600) and from the ink against the secondary ink, inside two interface sizes (15 and 14px). Every size is given at the 16px root, which grows with the window to 18px. Nothing is revealed only on hover: IDs, actions, the pin and the canvas's "+" are seen at rest.

Colour is restrained. One clinical blue marks selection, the active item, focus and links. Red, amber and green belong to the statuses. Seven muted project hues tint each project's folder mark and the workflow card tiles, so a project is recognised wherever it shows; nothing else is coloured. Dark and light are equally finished and follow the system setting unless the user picks one (`data-theme` on `html`).

The public site (`site/`, a static Next.js export on GitHub Pages with Fumadocs for the docs) wears the same world: the cool ground, the work on panels a step lighter with a hairline, 10px corners and shadow sm, Inter and Geist Mono, the one blue. The home page is a landing page composed in the dashboard's parts: a left-aligned two-sentence headline, the install command beside the primary action, a faux dashboard (the workflow canvas and its panel) that adds a step once, then file and session crops beside each command's facts, and lists of links as the dashboard's rows. The docs keep Fumadocs' routing, search and table of contents, restyled: the sidebar on the ground, the page on one inset panel, the dashboard's document scale one step up for a page that is only read. Each site section below ("The site") gives what differs from the dashboard; what it does not name is the dashboard's.

**Key Characteristics:**

- The sidebar on the ground, 244px, no border; the work area one inset panel with 10px corners and an 8px margin.
- A 44px header and a 40px row of pill tabs on every item page; one 16px gutter for header, tabs, title, document and canvas.
- Inter for the interface at 15px (14px for secondary labels), Geist Mono 14px for every ID and all code; both served by the dashboard itself.
- Lists of one-line 40px rows under a 32px sticky column head, grouped by 36px rounded bands on the band's tint.
- Every file edited whole in one Geist Mono 14/20 source editor over a 28px status bar (a Markdown file's `Source | Preview` switch in it); Discard and Save ⌘S always at the tab row's right, disabled while there is nothing to do.
- Documents at 17/24 in a 36rem column; a 22/28 title only over a workflow's Editor and History, never above a file.
- A root that grows with the window: 16px up to 1280px wide, 17px at 1920, 18px from 2560; every size grows with it.
- Facts in stacked property cards at the right: hairline, 8px corners, a 40px header on a half-strength band tint.
- Flat panels; shadows only on the work area, cards and what floats.
- The site: one 1344px column on the ground, a 52px headline (36px on a phone), the workflow demo across the column, panels with 10px corners and shadow sm; the docs' page on one inset panel beside the sidebar on the ground; a fixed 16px root.

### Named Rules

**The One Blue Rule.** Primary actions (a default button), a change's progress, selection, the active item, focus and links are blue, and nothing else is: checked controls and the logo are ink.

**The Status Is Colour Rule.** Red, amber and green mean Invalid, In progress and done. Nothing decorative takes them; the pinned star is ink.

**The Project Hue Rule.** A project hue marks a project (its folder) or a workflow step's kind (its tile), always as a small mark or a 20% tint, never as text, a fill behind text or a border.

## Typography

**Interface Font:** Inter Variable (`--font-sans`, also `--font-heading`: `"Inter Variable", system-ui, sans-serif`), weights 100 to 900 with optical sizes (`font-optical-sizing: auto` on `html`), served at `/fonts/inter.woff2` from `@fontsource-variable/inter`.
**Code Font:** Geist Mono Variable (`--font-mono`: `"Geist Mono Variable", ui-monospace, monospace`), served at `/fonts/geist-mono.woff2`. Both are embedded by `scripts/embed-fonts.ts`; nothing loads from another host.

**Character:** a neutral, screen-made sans for everything read and clicked, and a monospace for what would be typed: IDs, file names, paths, code, YAML.

Base: the root is `clamp(100%, 87.5% + 0.15625vw, 112.5%)` (`html` in `globals.css`): 16px (the browser's default) up to 1280px wide, 16.25px at 1440, 17px at 1920, 18px from 2560, as a share of the reader's own default. Every size below is given at the 16px root and grows with it: sizes are in rem, and the few a script takes in pixels (the canvas's cards, the file grids' columns, the docked panel's width) are multiplied by the root's scale (`hooks/use-root-scale.ts`). Text fields are `text-base` (16px) below 768px and `text-sm` (15px) from 768px. Tabular figures are set only where numbers line up (counts, ages and dates in a column, progress, the zoom, a version's time), never on the body: Inter's tabular hyphen is as wide as a digit and spaces out IDs and hyphenated words.

### Named Rules

**The Two Sizes Rule.** The interface is 15px and 14px, nothing else. Hierarchy inside it comes from 600, 500 and 400 and from the ink against the secondary ink. Only a dialog's title (18px) and a document's title (22px) are larger.

**The One Mono Rule.** Every ID and every line of code is Geist Mono 14px (`text-xs`), wherever it stands; an ID is never set in the sans, and never at another size.

**The Reading Scale Rule.** Documents read at 17/24 with headings 22, 19 and 17 (at 600), never outranking a 22px title; the interface around them stays at 15px.

**The Growing Root Rule.** The root grows with the window (16px up to 1280px, 17px at 1920, 18px from 2560), and every size grows with it: a box that holds text is never fixed in pixels, or its pixels are multiplied by the root's scale.

### Motion

- Hover and state changes: Tailwind's 150ms default, almost only `transition-colors`; the bands' and rows' carets turn with `transition-transform`.
- Overlays: fade and zoom from `tw-animate-css`, 100ms for dialogs, menus and popovers, 150ms for a sheet's dim. The sidebar folds and opens at once, with no width animation, so the work area never reflows frame by frame.
- A load shows nothing for 400ms, then a turning ring (`motion-safe:animate-spin`). Skeleton cells pulse.
- The canvas's fit, zoom and pan move at once, with no animation.
- A toast fades in and rises 8px over 150ms, and leaves the same way; at once under reduced motion.
- Reduced motion: transitions are limited to opacity and colours, and overlays no longer scale, slide or rotate.

## Do's and Don'ts

### Do

- **Do** take every colour from the tokens (`bg-background`, `text-muted-foreground`, `border-border`), never a literal, so both themes follow.
- **Do** keep the blue for primary actions, progress, selection, the active item, focus and links, and the status colours for status.
- **Do** set the interface in `text-sm` and `text-xs` only, with 600, 500 and 400 and the two inks carrying the hierarchy.
- **Do** set every ID in the `IdChip` (or Geist Mono `text-xs` where it is not a chip), and cut long names in the middle with `CutName`.
- **Do** build every list from `list-kit`: the sticky column head, `SectionBand`, 40px `ListRow`s, fixed `COLUMN` widths.
- **Do** keep one 16px gutter for header, tabs, title, document and canvas, and prose, code and tables to `--read-width` on the left edge.
- **Do** put an item's facts in `PropertyCard`s in the panel, and a workflow's title in `ItemHeading` over its Editor and History.
- **Do** edit every file whole in `FileEditor`, with `SaveControls` at the tab row's right and `Segmented` for any switch between views of one thing.
- **Do** show every empty, not-found, error and loading state with `StateBlock` (`EmptyNote`, `StateLoading`, `Notice`).
- **Do** use `tabular-nums` only where numbers line up.
- **Do** take the site's colours from its tokens in `site/app/global.css` (`bg-panel`, `text-dim`, `border-line`), each with the dashboard's value, and map Fumadocs' and the kit's colours onto them.
- **Do** set the site's mono in `text-code` (14px) and its interface in `text-ui` (15px); Tailwind's `text-xs` and `text-sm` are 12 and 14px there.
- **Do** put the site's boxes on the panel with a hairline, 10px corners and `shadow-panel`, and nothing else boxed.
- **Do** keep the workflow demo one picture (`role="img"`), skeleton but for the step added, played once in view and still under reduced motion.

### Don't

- **Don't** colour a checked control or the logo blue; they are ink. Only the primary action of a view is a blue button.
- **Don't** use a project hue as text, a fill behind text or a border, or give it to anything but a project's mark or a step tile.
- **Don't** add interface sizes beyond 15 and 14px, or document sizes beyond 22, 19 and 17px.
- **Don't** set tabular figures on body text; they space out hyphens in IDs and words.
- **Don't** hide IDs, actions, the pin or the canvas's "+" behind hover, or cut a title to a hover tooltip.
- **Don't** number section bands, draw rules between list rows, add zebra stripes or vertical column rules.
- **Don't** put shadows on the sidebar, bands, rows or documents.
- **Don't** edit a part of a file in place on a file page (a pencil, a field on a title or a task), put a title above a file, or give the change panel an edit control; it is read-only.
- **Don't** load fonts, scripts or images from another host; the CSP allows only the dashboard's own.
- **Don't** bring back the old site's amber accent, warm paper ground, dashed guide lines with crosses, square corners or Unbounded wordmark, and don't load the site's fonts from another host.
